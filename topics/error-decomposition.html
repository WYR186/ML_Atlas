Error Decomposition

Lecture 21 uses error decomposition to explain why model choice is a trade-off. Total test error is not one blob; it has an irreducible part, a model-class part, and a finite-data part.

1. Concept Understanding

Fix a hypothesis class $\mathcal{F}$, such as linear classifiers, decision trees, kernels, or neural networks. For any learned predictor $f\in\mathcal{F}$, its test error can be decomposed into three conceptual pieces.

  • Bayes error: noise inherent in the data distribution, such as overlapping class distributions. This is the irreducible floor.
  • Approximation error: the best function inside $\mathcal{F}$ may still be worse than the Bayes rule. This depends on the expressiveness of $\mathcal{F}$, not directly on sample size $n$.
  • Estimation error: the learned $f$ may be worse than the best function in $\mathcal{F}$ because training data is finite. ERM optimizes empirical risk, which is only an estimate of true risk. PAC sample-complexity results are mainly designed to control this term.

2. Plain-English Explanation

Think of trying to copy a complicated drawing. Some parts are blurry in the original picture: that is Bayes error. Your pen might be too thick to draw fine details: that is approximation error. And even with a good pen, your hand might miss the best drawing because you only got a few practice examples: that is estimation error.

3. Core Intuition

A richer model class can represent more patterns, so approximation error tends to decrease. But if the dataset size is fixed, a richer class is easier to overfit, so estimation error can increase.

This is the theory version of the bias-variance style trade-off: simple class means underfitting risk; overly rich class means generalization risk.

As sample size $n$ grows, estimation error usually shrinks for a fixed class. As complexity grows, estimation error can grow because there are more hypotheses that may accidentally look good on a finite sample.

4. Key Equations

Total error split
$$ \epsilon_\mu(f)= \underbrace{\left(\epsilon_\mu(f)-\inf_{g\in\mathcal{F}}\epsilon_\mu(g)\right)}_{\text{estimation error}} +\underbrace{\left(\inf_{g\in\mathcal{F}}\epsilon_\mu(g)-\epsilon_\mu^*\right)}_{\text{approximation error}} +\underbrace{\epsilon_\mu^*}_{\text{Bayes error}} $$

What it does. The equality adds and subtracts the same best-in-class error. The first gap asks how far the learned $f$ is from the best member of $\mathcal{F}$. The second gap asks how far the best member of $\mathcal{F}$ is from Bayes optimal. The last term is irreducible noise.

Squared-loss cousin: bias, variance, noise
$$ \mathbb{E}\big[(\hat f(x)-y)^2\big]=\mathrm{Bias}(\hat f(x))^2+\mathrm{Var}(\hat f(x))+\mathrm{Noise} $$

What it does. For regression with squared loss, the same diagnosis appears as bias, variance, and noise. Noise parallels Bayes error; bias roughly tracks model-class mismatch; variance tracks how much the learned predictor changes across training sets.

Best-in-class predictor
$$ f_{\mathcal{F}}^*\in\arg\min_{g\in\mathcal{F}}\epsilon_\mu(g) $$

What it does. This names the ideal predictor inside the chosen hypothesis class. It is the benchmark for estimation error, even though the learner does not know it directly.

Learned predictor
$$ \hat f=\mathcal{A}(\mathcal{D}) $$

What it does. This says the actual predictor is the output of an algorithm applied to a finite random dataset, so it can change when the sample changes.

How to apply it in questions
If sample size changes: focus on estimation error, because $\hat f$ has more or less data to find the best member of $\mathcal{F}$.
If the question mentions PAC, VC dimension, or sample complexity: it is usually asking how many samples are needed to control estimation/generalization error.
If the model class changes: focus on approximation error, because the best-in-class benchmark itself may move.
If the label noise or distribution changes: focus on Bayes error, because the irreducible lower bound changed.
Diagnosis guide
High training error: suspect high approximation error / underfitting. Increase model complexity, add useful features, or switch to a richer $\mathcal{F}$.
Low training error but high validation error: suspect high estimation error / overfitting. Add data, regularize, or simplify $\mathcal{F}$.
Both training and test error hit the same floor: the remaining gap may be Bayes error from label noise or overlapping classes.

5. Worked Examples

Example 1 · Polynomial degree

Source: Lecture 21, pp. 19-23.

A low-degree polynomial cannot follow a wavy target, so approximation error is large. Increasing degree reduces approximation error, but with limited samples the fitted curve may chase noise, increasing estimation error.

Example 2 · Constant classifiers

Source: Lecture 21, p. 14.

If $\mathcal{F}$ contains only constant binary classifiers, the best-in-class error is the minority-class probability. If features actually contain useful information, this can be much worse than Bayes error.

Example 3 · More data with the same class

Source: Lecture 21, p. 23 and Lecture 22, p. 27.

With fixed $\mathcal{F}$, adding data mainly attacks estimation error. It does not change the Bayes error or make a weak model class more expressive.

6. Problem-Solving Tips

  1. Ask whether the issue comes from data noise, model expressiveness, or finite samples.
  2. More data usually points to estimation error.
  3. A larger model class usually points to approximation error going down and estimation error risk going up, especially when VC dimension / parameter count increases faster than data.
  4. Changing the data-generating distribution can change Bayes error.
  5. Do not call approximation error overfitting; overfitting is usually an estimation/generalization problem.
  6. Use train-vs-validation behavior to decide whether to collect more data or change the model class.

7. Common Mistakes

  • Saying Bayes error decreases when we collect more data. It does not; it is tied to $\mu$.
  • Saying a richer model always improves test error. It can overfit when data is limited.
  • Mixing up approximation error and estimation error: one is about $\mathcal{F}$, the other is about $\mathcal{D}$ and learning.
  • Forgetting the best-in-class term $\inf_{g\in\mathcal{F}}\epsilon_\mu(g)$ when writing the decomposition.

8. Exam Focus

  • Be able to write the three-term decomposition.
  • Explain that Bayes error is the irreducible lower bound inside the decomposition.
  • Know which term changes when $\mathcal{F}$ becomes more expressive.
  • Know which term decreases with more samples for fixed $\mathcal{F}$.
  • Connect PAC and VC bounds to estimation error, not approximation error or Bayes error.
  • Explain the approximation-estimation trade-off in words.
  • Connect high training error to underfitting and low-train/high-test error to overfitting.
  • Recognize how bias-variance-noise under squared loss parallels, but is not identical to, the three-term true-risk split.

9. Quick Checklist

  • Bayes error = irreducible noise.
  • Approximation error = model class too limited.
  • Estimation error = finite-data learning gap.
  • PAC / VC sample complexity controls estimation error.
  • More expressive class: approximation down, estimation risk up.
  • More data: estimation down, Bayes/approximation unchanged.
  • High train error means try richer $\mathcal{F}$; low train but high validation means regularize, simplify, or collect data.

Error Decomposition · 误差分解

Lecture 21 用 error decomposition 解释为什么“模型越复杂越好”是错的。测试误差不是一坨东西，而是可以拆成数据噪声、模型表达能力、有限样本学习误差三部分。

1. Concept Understanding · 概念理解

固定一个 hypothesis class $\mathcal{F}$，比如 linear classifier、decision tree、kernel machine 或 neural network。对任意学出来的 $f\in\mathcal{F}$，test error 可以分成三块：

  • Bayes error：数据分布本身的噪声，比如 class distributions 重叠；这是不可消除的理论下界。
  • Approximation error：$\mathcal{F}$ 里最好的函数仍然不够接近 Bayes rule；它由 $\mathcal{F}$ 的 expressiveness 决定，不直接由样本量 $n$ 决定。
  • Estimation error：训练数据有限，学到的 $f$ 没有达到 $\mathcal{F}$ 内真实最优；ERM 最小化的是 empirical risk，而它只是 true risk 的估计。PAC sample complexity 主要控制的就是这一项。

2. Plain-English Explanation · 大白话理解

像临摹一张图：原图有些地方本来就糊，这是 Bayes error；你的笔太粗，画不出细节，这是 approximation error；你练习样本太少，手没画稳，这是 estimation error。

3. Core Intuition · 核心直觉

模型类越强，能表达的函数越多，approximation error 往往更小。但训练集大小固定时，模型越灵活也越容易追着样本噪声跑，estimation error 风险会变大。

这就是 theory 版本的 underfitting / overfitting trade-off：太简单会表达不足，太复杂会泛化不稳。

当 sample size $n$ 变大，固定 $\mathcal{F}$ 下 estimation error 通常下降；当 complexity 变大，可选 hypotheses 更多，有限样本上“碰巧训练误差低”的坏模型也更多，estimation risk 会上升。

4. Key Equations · 关键公式

总误差分解
$$ \epsilon_\mu(f)= \underbrace{\left(\epsilon_\mu(f)-\inf_{g\in\mathcal{F}}\epsilon_\mu(g)\right)}_{\text{estimation error}} +\underbrace{\left(\inf_{g\in\mathcal{F}}\epsilon_\mu(g)-\epsilon_\mu^*\right)}_{\text{approximation error}} +\underbrace{\epsilon_\mu^*}_{\text{Bayes error}} $$

符号：下面的 bullet list 逐项解释公式里的变量。

  • $\epsilon_\mu(f)$ 是 predictor $f$ 在真实数据分布 $\mu$ 下的 true/test error。
  • $\mathcal{F}$ 是允许使用的 hypothesis class，比如 linear classifier、tree。
  • $g\in\mathcal{F}$ 表示“$\mathcal{F}$ 里的任意一个 candidate predictor”。
  • $\inf_{g\in\mathcal{F}}\epsilon_\mu(g)$ 是 $\mathcal{F}$ 内能达到的最小 true error。
  • $\epsilon_\mu^*$ 是 Bayes error，也就是不限制在 $\mathcal{F}$ 时的理论最低错误。

怎么理解：这个等式本质是加减同一个 best-in-class error。第一项看学出来的 $f$ 离 $\mathcal{F}$ 内最优还有多远；第二项看 $\mathcal{F}$ 内最优离 Bayes optimal 还有多远；最后一项是数据本身噪声。

怎么用：固定 $\mathcal{F}$ 时加数据主要降低 estimation error；换更强的 $\mathcal{F}$ 可能降低 approximation error，但 estimation 更难；只换算法不能消掉 Bayes error。

Squared-loss 对照：bias, variance, noise
$$ \mathbb{E}\big[(\hat f(x)-y)^2\big]=\mathrm{Bias}(\hat f(x))^2+\mathrm{Var}(\hat f(x))+\mathrm{Noise} $$

怎么理解：对 squared loss regression，同类诊断常写成 bias、variance、noise。Noise 对应 Bayes error 这种 irreducible part；bias 大致对应模型类不够贴近真函数；variance 衡量不同 training sets 下学出的 predictor 波动有多大。

怎么用：不要把两套公式机械等同。Error decomposition 固定 hypothesis class $\mathcal{F}$ 写 true risk；bias-variance-noise 是 squared loss 下对 training-set randomness 取 expectation。

Best-in-class predictor
$$ f_{\mathcal{F}}^*\in\arg\min_{g\in\mathcal{F}}\epsilon_\mu(g) $$

符号：下面的 bullet list 逐项解释公式里的变量。

  • $f_{\mathcal{F}}^*$ 是 $\mathcal{F}$ 内 true error 最小的某个 predictor。
  • $\arg\min$ 返回的是“让误差最小的函数”，不是最小误差数值本身。
  • 星号表示 optimal，下标 $\mathcal{F}$ 表示“只在这个 class 里面最优”。

怎么理解：这是选定 $\mathcal{F}$ 后的理论最佳模型，是 estimation error 的参照物；真实训练算法通常不知道它，只能用有限数据去靠近。

怎么用：题目问有限样本学习差距时，把实际学到的 $\hat f$ 和 $f_{\mathcal{F}}^*$ 比。

Learned predictor
$$ \hat f=\mathcal{A}(\mathcal{D}) $$

符号：下面的 bullet list 逐项解释公式里的变量。

  • $\mathcal{D}$ 是 training set。
  • $\mathcal{A}$ 是 learning algorithm，比如 ERM、SVM training、tree induction。
  • $\hat f$ 上面的 hat 表示它依赖数据；训练集换了，$\hat f$ 可能也会变。

怎么理解：实际 predictor 是 learning algorithm 在一个有限随机训练集上的输出；换一份 $\mathcal{D}$，$\hat f$ 可能就变。

怎么用：只要 predictor 是从有限 $\mathcal{D}$ 里学出来的，就要考虑 estimation error。

题目里怎么套
如果 sample size 变了：优先看 estimation error，因为 $\hat f$ 有更多或更少数据去接近 $\mathcal{F}$ 内最优。
如果题目提 PAC、VC dimension 或 sample complexity：通常是在问需要多少样本来控制 estimation / generalization error。
如果 model class 变了：优先看 approximation error，因为 best-in-class benchmark 本身可能变了。
如果 label noise / distribution 变了：优先看 Bayes error，因为不可消除的理论下界变了。
诊断指南
Training error 很高：优先怀疑 high approximation error / underfitting。解法是增加 model complexity、加有效 features，或换更强的 $\mathcal{F}$。
Training error 很低但 validation/test error 很高：优先怀疑 high estimation error / overfitting。解法是加数据、regularization，或简化 $\mathcal{F}$。
Train/test 都降到同一个下界附近：剩下部分可能来自 Bayes error，比如 label noise 或 class overlap。

5. Worked Examples · 代表性例题

例 1 · polynomial degree

出处：Lecture 21, pp. 19-23。

低阶 polynomial 拟合不了波动很细的目标，approximation error 大。提高 degree 后表达能力变强，但样本有限时可能追着噪声走，estimation error 变大。

例 2 · 只有 constant classifier

出处：Lecture 21, p. 14。

如果 $\mathcal{F}$ 只有常数二分类器，best-in-class error 就是少数类概率。如果 feature 里其实有有效信息，这个误差会明显高于 Bayes error。

例 3 · 固定模型类时加数据

出处：Lecture 21, p. 23；Lecture 22, p. 27。

固定 $\mathcal{F}$ 时，更多数据主要降低 estimation error。它不会改变 Bayes error，也不会让弱模型类突然能表达更复杂函数。

6. Problem-Solving Tips · 解题技巧

  1. 先判断问题来自 data noise、model expressiveness，还是 finite samples。
  2. “更多数据”通常对应 estimation error。
  3. “更强模型类”通常让 approximation error 下降，但 estimation risk 上升，尤其是 VC dimension / 参数量相对数据增长太快时。
  4. 改变数据生成分布才可能改变 Bayes error。
  5. 不要把 approximation error 叫 overfitting；overfitting 通常是 estimation / generalization 问题。
  6. 用 training-vs-validation behavior 判断是该收集更多数据，还是该换模型类。

7. Common Mistakes · 常见错误

  • 说 Bayes error 会因为加数据而下降。它由 $\mu$ 决定，不由样本量决定。
  • 说更复杂模型一定提高 test performance。数据不足时可能 overfit。
  • 混淆 approximation 与 estimation：前者看 $\mathcal{F}$，后者看 $\mathcal{D}$ 和 learning。
  • 写公式时漏掉 best-in-class 项 $\inf_{g\in\mathcal{F}}\epsilon_\mu(g)$。

8. Exam Focus · 考试重点

  • 会默写三项 error decomposition。
  • 会说明 Bayes error 在分解里是不可消除的 lower bound。
  • 知道 $\mathcal{F}$ 更 expressive 时哪些项变化。
  • 知道固定 $\mathcal{F}$ 时更多 samples 主要降低 estimation error。
  • 能把 PAC / VC bounds 对应到 estimation error，而不是 approximation error 或 Bayes error。
  • 能用文字解释 approximation-estimation trade-off。
  • 能把 high training error 对应到 underfitting，把 low-train/high-test error 对应到 overfitting。
  • 能识别 squared loss 下的 bias-variance-noise 与三项 true-risk 分解的相似处和区别。

9. Quick Checklist · 速记清单

  • Bayes error = irreducible noise。
  • Approximation error = 模型类太弱。
  • Estimation error = 有限数据导致的学习差距。
  • PAC / VC sample complexity 控制的是 estimation error。
  • 模型类更强：approximation 下降，estimation 风险上升。
  • 数据更多：estimation 下降，Bayes / approximation 不变。
  • Train error 高就考虑更强 $\mathcal{F}$；train 低但 validation 高就 regularize、简化模型或加数据。
