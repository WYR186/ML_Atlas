Auto-encoder

An auto-encoder learns a representation by asking a neural network to compress an input and then reconstruct it. The important formula idea is simple: if the reconstruction must pass through a bottleneck, the hidden code must keep the useful structure of the input.

1. Concept Understanding

An auto-encoder has two parts. The encoder maps the original input into a code, and the decoder maps the code back into the input space. Training minimizes the mismatch between the original input and the reconstruction.

  • Encoder: turns $x$ into a learned representation $z$.
  • Decoder: turns $z$ into a reconstruction $\hat{x}$.
  • Loss: measures how different $\hat{x}$ is from $x$.

2. Plain-English Explanation

Think of the encoder as making a compact study note from a full lecture, and the decoder as trying to recreate the lecture from that note. If the note is too short to copy everything, it has to capture the important patterns.

That is why auto-encoders are useful for representation learning: the model is forced to answer, “What information do I need to keep so I can rebuild the input?”

3. Core Intuition

A useful auto-encoder is not just a copying machine. It works when the architecture or regularization prevents exact memorization, so the code $z$ captures stable factors such as shape, stroke style, topic, or semantic content.

Connection to PCA

A linear, undercomplete auto-encoder behaves like PCA: it learns a low-dimensional subspace that preserves as much reconstruction information as possible. Nonlinear activations let the model learn curved manifolds instead of only flat subspaces.

4. Key Equations

Encoder / decoder
$$ z=f_\phi(x),\qquad \hat{x}=g_\theta(z) $$

Symbols. $x$: Original input, such as an image or feature vector.； $f_\phi$: Encoder network with trainable parameters $\phi$.； $z$: Latent code, embedding, or bottleneck representation.； $g_\theta$: Decoder network with trainable parameters $\theta$.； $\hat{x}$: Reconstructed version of the input.

How to read it. The encoder compresses; the decoder tests whether the compressed code kept enough information to rebuild the input.

How to use. Compute $z=f_\phi(x)$ first, then decode $\hat{x}=g_\theta(z)$. The code $z$ can be used as a learned feature vector after training.

Reconstruction loss
$$ \min_{\theta,\phi}\;\mathcal{L}_{rec}(x,\hat{x}) $$
$$ \mathcal{L}_{rec}=\|x-\hat{x}\|_2^2\quad\text{(MSE)} $$

Symbols. $\mathcal{L}_{rec}$: Reconstruction loss; smaller means the output looks closer to the input.； $\|x-\hat{x}\|_2^2$: Squared Euclidean distance between input and reconstruction.； $\min_{\theta,\phi}$: Optimize both decoder parameters $\theta$ and encoder parameters $\phi$.； MSE: Mean squared error, often averaged over pixels/features and a minibatch.

How to read it. The loss is a copying test. With a bottleneck or regularizer, doing well on this test requires learning reusable structure rather than memorizing raw input.

How to use. For each minibatch, reconstruct every input, compute squared errors, average them, then backpropagate through decoder and encoder.

6. Problem-Solving Tips

  • Start by identifying the input $x$, code $z$, and reconstruction $\hat{x}$.
  • If the question asks why the representation is meaningful, point to the bottleneck or regularization.
  • For MSE, compute elementwise differences, square them, then sum or average depending on the convention.
  • For denoising variants, remember that the model receives corrupted input but targets clean input.

7. Common Mistakes

  • Assuming every auto-encoder learns useful features. Without constraints, a large model can simply memorize.
  • Mixing up $x$ and $\hat{x}$: $x$ is the target input, while $\hat{x}$ is the model output.
  • Calling $z$ a probability distribution. In a plain auto-encoder, $z$ is usually a deterministic code.
  • Confusing a plain auto-encoder with a VAE. A VAE adds a probabilistic latent variable and a KL term.

8. Exam Focus

  • Write $z=f_\phi(x)$ and $\hat{x}=g_\theta(z)$ from memory.
  • Explain what the reconstruction loss is minimizing.
  • Explain why an undercomplete or regularized auto-encoder avoids trivial copying.
  • Compare a linear auto-encoder with PCA at a high level.

Auto-encoder · 自编码器

Auto-encoder 用“压缩再重建”的任务学习 representation。公式的核心不是复杂概率，而是：输入必须经过一个 code $z$ 才能重建，所以 $z$ 会被迫保留输入里的重要结构。

1. Concept Understanding

Auto-encoder 分成 encoder 和 decoder。Encoder 把原始输入压到 latent code，decoder 再从 code 还原输入。训练目标就是让还原出来的 $\hat{x}$ 尽量接近原来的 $x$。

  • Encoder：把 $x$ 变成 learned representation $z$。
  • Decoder：把 $z$ 变回 reconstruction $\hat{x}$。
  • Loss：衡量 $\hat{x}$ 和 $x$ 差多少。

2. Plain-English Explanation / 大白话理解

可以把 encoder 想成“给一整节课做压缩笔记”，decoder 想成“只看笔记把这节课复原出来”。如果笔记空间很小，就没法逐字复制，只能抓重点。

所以 auto-encoder 学 representation 的关键问题是：为了重建输入，哪些信息最值得保留？

3. Core Intuition

好的 auto-encoder 不应该只是复制器。它有效的前提是 architecture 或 regularization 阻止它死记硬背，让 $z$ 学到稳定因素，比如形状、笔画风格、主题或语义内容。

和 PCA 的关系

线性、undercomplete 的 auto-encoder 很像 PCA：都在找一个低维空间，尽量保留 reconstruction 所需的信息。加入 nonlinear activation 后，AE 可以学习弯曲的 manifold，而不只是平面 subspace。

4. Key Equations

Encoder / decoder
$$ z=f_\phi(x),\qquad \hat{x}=g_\theta(z) $$

符号. $x$: 原始输入，比如图片或 feature vector。；$f_\phi$: Encoder network，参数是 $\phi$。；$z$: Latent code / embedding / bottleneck representation。；$g_\theta$: Decoder network，参数是 $\theta$。；$\hat{x}$: 模型重建出来的输入。

怎么理解. Encoder 负责压缩，decoder 检验这个压缩后的 code 是否保留了足够信息来重建输入。

怎么用. 先算 $z=f_\phi(x)$，再 decode 得到 $\hat{x}=g_\theta(z)$。训练后，$z$ 可以当作 learned feature vector 使用。

Reconstruction loss
$$ \min_{\theta,\phi}\;\mathcal{L}_{rec}(x,\hat{x}) $$
$$ \mathcal{L}_{rec}=\|x-\hat{x}\|_2^2\quad\text{(MSE)} $$

符号. $\mathcal{L}_{rec}$: Reconstruction loss；越小表示输出越接近输入。；$\|x-\hat{x}\|_2^2$: 输入和 reconstruction 之间的 squared Euclidean distance。；$\min_{\theta,\phi}$: 同时优化 decoder 参数 $\theta$ 和 encoder 参数 $\phi$。；MSE: Mean squared error，通常会对像素/特征和 minibatch 求平均。

怎么理解. 这个 loss 像一个“复原测试”。有 bottleneck 或 regularizer 时，想复原得好就必须学习可复用结构，而不能只死记硬背。

怎么用. 对每个 minibatch，先重建所有输入，再计算 squared error，取平均，然后通过 decoder 和 encoder 做 backpropagation。

6. Problem-Solving Tips

  • 先标出 input $x$、code $z$、reconstruction $\hat{x}$。
  • 题目问 representation 为什么有意义，就回答 bottleneck 或 regularization 限制了 trivial copying。
  • 算 MSE 时先逐元素相减，再平方，最后按题目要求 sum 或 average。
  • Denoising AE 要记住：输入是 corrupted input，目标是 clean input。

7. Common Mistakes

  • 以为所有 auto-encoder 都自动学到好特征；如果容量太大又没约束，可能只是 memorization。
  • 混淆 $x$ 和 $\hat{x}$：$x$ 是目标输入，$\hat{x}$ 是模型输出。
  • 把 $z$ 当作概率分布；plain AE 里的 $z$ 通常是 deterministic code。
  • 把 plain AE 和 VAE 混在一起；VAE 多了 probabilistic latent variable 和 KL term。
