1. Concept Understanding

A large language model is a decoder-only Transformer trained to predict the next token from previous tokens. The model learns a probability distribution over the vocabulary at every position, then generation repeatedly samples one token and feeds it back into the context.

  • Lecture 18: architecture, tokenization, final prediction, and decoding.
  • Lecture 19: pre-training objective, perplexity, SFT, alignment, LoRA, and limitations.
  • HW4: positional encoding, attention, multi-head attention, and parameter counting for a decoder-only LLM.

Language modeling. The core supervised-looking task is next-token prediction: estimate $P_\theta(x_t\mid x_1,\ldots,x_{t-1})$ from raw text.

Token pipeline. Text is first split into subword tokens, often by BPE, which repeatedly merges frequent adjacent token pairs. Token IDs become vectors through a learnable embedding table; position information is added so the Transformer knows order.

Scaling hypothesis. Much of modern LLM progress comes from scaling model size and training data together, so the same next-token objective supports many emergent capabilities.

2. Plain-English Explanation

An LLM is an extremely practiced autocomplete system. It reads the current context, turns it into vectors, runs many Transformer blocks, and asks: "which token is most plausible next?"

The surprising part is scale. If the model sees enough text and has enough capacity, next-token prediction forces it to internalize grammar, facts, style, reasoning patterns, and code patterns because all of those help predict the next token.

3. Core Intuition

The training target is simple, but the hidden task is rich. To predict the next token well, the model often needs to identify topic, syntax, entities, long-range dependencies, and likely user intent. The decoder-only Transformer is efficient because all next-token losses for a training sequence can be computed in one parallel forward pass.

Base models are document continuers. Instruction-tuned models are assistants. That distinction is the reason Lecture 19 separates pre-training from post-training.

Training pipeline. Pre-training uses self-supervised NLL on massive unlabeled text. SFT then imitates human-written instruction-response pairs. RLHF uses human preferences or rankings to push outputs toward being helpful, honest, and harmless.

RL view. During LLM reinforcement learning, the state is the prompt plus generated tokens so far, the action is the next token, and the policy is the model's next-token distribution. GRPO-style methods compare multiple completions for the same prompt to estimate relative advantages without a separate value model.

  • Encoder-only models, such as BERT, use bidirectional attention and masked language modeling, which fits classification and language-understanding tasks.
  • Decoder-only models, such as GPT, use causal attention and next-token prediction, which fits open-ended generation.
  • Vision Transformers split images into patches, treat patches as tokens, and usually need more data than CNNs because they have less built-in locality bias.

4. Key Equations

Autoregressive factorization

$$ P_\theta(x_1,\ldots,x_T)=\prod_{t=1}^{T}P_\theta(x_t\mid x_{\lt t}) $$

Symbols. $x_t$ is the token at position $t$; $x_{\lt t}$ means all earlier tokens; $T$ is sequence length; $\theta$ denotes model parameters.

How to read it. A language model assigns probability to a whole sequence by predicting one token at a time. The probability of the full sequence is the product of all next-token probabilities.

How to use. For training-loss derivations, take the log of this product to turn it into a sum, then negate it to get NLL.

Next-token probability

$$ P_\theta(x_t=i\mid x_{\lt t})=\frac{\exp(z_{t,i})}{\sum_{j\in V}\exp(z_{t,j})} $$

Symbols. $z_{t,i}$ is the logit for token $i$ at position $t$; $V$ is the vocabulary set; $j\in V$ means the denominator sums over every candidate token.

How to read it. The LM head produces one logit for every vocabulary token. Softmax converts those logits into probabilities.

How to use. To compare two candidate tokens, compare their logits. To compute an actual probability, exponentiate each logit and normalize by the vocabulary-wide sum.

Token embedding plus position

$$ h_t^{(0)}=E[x_t]+p_t,\qquad E\in\mathbb{R}^{|V|\times D} $$

Symbols. $E$ is the learnable token embedding table, $|V|$ is vocabulary size, $D$ is hidden size, $E[x_t]$ is the row vector for token $x_t$, and $p_t$ is the positional encoding or position embedding for position $t$.

How to read it. A token ID by itself is just an index. The model starts by turning it into a $D$-dimensional vector and adding order information because self-attention without positions is permutation equivariant.

Position detail. The original Transformer used fixed sinusoidal signals; many LLMs use learned or rotary variants. The exam-level idea is the same: inject token order.

How to use. For parameter counts, the input embedding table contributes about $VD$ parameters. If output embeddings are separate, the LM head contributes another $VD$.

NLL / cross-entropy loss

$$ \mathcal{L}(X;\theta)=-\frac{1}{T}\sum_{t=1}^{T}\log P_\theta(x_t\mid x_{\lt t}) $$

Symbols. $X=(x_1,\ldots,x_T)$ is the token sequence. $T$ is sequence length. $\theta$ are model parameters. $P_\theta(x_t\mid x_{\lt t})$ is the probability the model assigns to the correct next token at position $t$.

How to read it. The loss penalizes the model whenever it assigns low probability to the true next token. Averaging by $T$ makes examples of different lengths comparable.

How to use. If the model gives probabilities $p_1,\ldots,p_T$ to the correct tokens, plug in $-\frac1T\sum_t \log p_t$.

Perplexity

$$ PP(X)=\exp(\mathcal{L}(X;\theta))=\left(\prod_{t=1}^T P_\theta(x_t\mid x_{\lt t})\right)^{-1/T} $$

Symbols. $PP(X)$ is perplexity. $\mathcal{L}(X;\theta)$ is average NLL. The product multiplies the correct-token probabilities across positions, and exponent $-1/T$ turns that product into an inverse geometric mean.

How to read it. Perplexity is exponentiated average NLL. A perplexity of 4 means the model is, on average, as uncertain as choosing uniformly among 4 options.

How to use. First compute average NLL, then exponentiate. If all correct-token probabilities are equal to $p$, then perplexity is $1/p$.

Temperature decoding

$$ P_T(i)=\mathrm{softmax}\!\left(\frac{z_i}{T}\right) $$

Symbols. $z_i$ is the logit for candidate token $i$. $T>0$ is decoding temperature, not sequence length here. $P_T(i)$ is the sampling probability after dividing logits by temperature and applying softmax.

How to read it. Temperature rescales logits before softmax. Smaller $T$ makes the distribution sharper; larger $T$ makes it flatter.

How to use. For any finite $T>0$, greedy top-1 does not change because dividing by a positive constant preserves logit order. Sampling changes because probabilities become sharper or flatter.

LoRA update

$$ W = W_0+\Delta W,\qquad \Delta W=BA,\qquad r\ll \min(d,k) $$

Symbols. If $W_0\in\mathbb{R}^{d\times k}$, then $B\in\mathbb{R}^{d\times r}$ and $A\in\mathbb{R}^{r\times k}$. The rank $r$ is much smaller than $d$ or $k$, so the update is cheap.

How to read it. LoRA freezes the original weight $W_0$ and learns a low-rank update $\Delta W$ instead of a full matrix.

How to use. Parameter count is $dr+rk$ instead of $dk$. For a square $D\times D$ matrix, some notes write the equivalent convention $\Delta W=AB$ with $A\in\mathbb{R}^{D\times R}$ and $B\in\mathbb{R}^{R\times D}$, giving $2DR$ trainable parameters instead of $D^2$.

Decoder-only parameter count

$$ N_{\mathrm{params}}\approx L(4D^2+2DF)+2VD $$

Symbols. $L$ is the number of decoder layers, $D$ is hidden size, $F$ is MLP hidden width, and $V$ is vocabulary size.

How to read it. Each layer has about $4D^2$ attention parameters for $Q,K,V,O$ projections and $2DF$ MLP parameters for the two linear maps. The $2VD$ term counts input and output embedding matrices.

How to use. This is the HW4-style back-of-the-envelope count. It usually ignores smaller terms such as biases and LayerNorm; if embeddings are tied, the embedding term changes.

5. Worked Examples

Lecture 19: perplexity from three correct-token probabilities

Source: Lecture 19, paraphrased.

If the model assigns probability $0.25$ to each of three true next tokens, then

$$ PP=(0.25\cdot 0.25\cdot 0.25)^{-1/3}=4 $$

Interpretation: on average, the model is as uncertain as choosing uniformly among four plausible next tokens.

Lecture 18: top-1 under temperature

Temperature rescales all logits by $1/T$. The highest logit remains the highest for $T>0$, so greedy top-1 does not change. Sampling behavior does change: small $T$ is sharper; large $T$ is flatter.

Lecture 18: decoding menu

Greedy decoding picks the most likely next token and can fall into repetitive loops. Beam search keeps the best $B$ partial sequences at each step. Top-k and top-p sampling restrict the candidate pool before sampling, trading off coherence and diversity.

HW4 §2.4: simplified decoder-only parameter count

For the OLMo-style configuration in HW4, the simplified formula $L(4D^2+2DF)+2VD$ gives about 5.45B parameters. This is why the feed-forward width and vocabulary matrices matter so much.

Lecture 19: prompting and in-context learning

Zero-shot prompting gives only the task instruction. Few-shot prompting adds a few input-output examples so the model can infer the pattern without gradient updates. Chain-of-thought prompting asks for intermediate reasoning, which can improve multi-step tasks.

6. Problem-Solving Tips

  1. For training objective questions, start with autoregressive factorization, then take negative log.
  2. For perplexity, remember "exponential of average NLL."
  3. For tokenization questions, compare word-level, character-level, and subword BPE tradeoffs.
  4. For post-training questions, separate SFT from RLHF: SFT imitates demonstrations; RLHF optimizes preferences, often by treating generation as an MDP over tokens.
  5. For decoding questions, distinguish choosing a token from changing the probability distribution.
  6. Greedy decoding picks the highest-probability token; beam search keeps the best $B$ partial sequences; top-k samples from the $k$ most likely tokens; top-p samples from the smallest set whose cumulative probability reaches $p$.
  7. For parameter counts, remember attention $4D^2$, MLP $2DF$, and input/output embeddings $2VD$ under the simplified HW4 convention.
  8. For prompting questions, zero-shot means no examples, few-shot means examples in the prompt, and in-context learning means no gradient update.

7. Common Mistakes

  • Calling a base model an instruction follower. A base model is primarily a document continuer.
  • Forgetting to mask system/user tokens during SFT loss when the target is assistant-only generation.
  • Thinking lower perplexity always means safer or more truthful output. It measures predictive likelihood, not truth.
  • Forgetting that Transformers need position information; token embeddings alone do not encode order.
  • Confusing beam search with sampling. Beam search searches high-likelihood sequences; sampling intentionally injects randomness.
  • Sampling from all tokens without top-k/top-p filtering, which can select extremely low-probability nonsense tokens.
  • Assuming LoRA updates all weights. It freezes $W_0$ and trains small low-rank matrices.

9. Quick Checklist

  • LLM = decoder-only Transformer + next-token prediction.
  • Autoregressive means full sequence probability is a product of next-token probabilities.
  • BPE balances vocabulary size and sequence length.
  • Embeddings use a $V\times D$ table, and positional encoding supplies token order.
  • BERT is encoder-only; GPT is decoder-only; ViT treats image patches as tokens.
  • LM head maps hidden state to vocabulary logits.
  • Perplexity = $\exp(\text{average NLL})$.
  • Greedy, beam search, top-k, top-p, and temperature are decoding choices.
  • SFT teaches instruction following; RLHF aligns HHH-style preferences.
  • LLM RL treats next-token generation as policy actions.
  • LoRA trains low-rank adapters, not the full matrix.
  • Few-shot and chain-of-thought are prompting methods, not gradient updates.

1. 概念理解 / Concept Understanding

Large Language Model 是一个 decoder-only Transformer，训练目标是根据过去 tokens 预测下一个 token。模型在每个位置输出整个 vocabulary 上的概率分布；生成时反复采样下一个 token，再把它接回 context。

  • Lecture 18：architecture、tokenization、final prediction、decoding。
  • Lecture 19：pre-training objective、perplexity、SFT、alignment、LoRA、limitations。
  • HW4：positional encoding、attention、multi-head attention、decoder-only LLM 参数量。

Language modeling. 核心任务是 next-token prediction：从 raw text 中学习 $P_\theta(x_t\mid x_1,\ldots,x_{t-1})$。

Token pipeline. 文本先通过 BPE 这类 subword tokenizer 切成 tokens；BPE 会反复 merge 最高频的 adjacent token pairs。Token IDs 通过 learnable embedding table 变成向量；再加 positional encoding，让 Transformer 知道 token order。

Scaling hypothesis. 现代 LLM 的很多能力来自 model size 和 training data 一起 scale up；同一个 next-token objective 在足够规模下会支持很多复杂能力。

2. 大白话理解 / Plain-English Explanation

LLM 可以先理解成一个“练到极致的 autocomplete”。它读当前上下文，把文字变成向量，经过很多 Transformer blocks，然后问自己：“下一个 token 最可能是什么？”

神奇的地方在 scale。只要文本够多、模型够大，next-token prediction 会逼着模型学语法、事实、风格、推理模式、代码模式，因为这些都能帮它更好预测下一个 token。

3. 核心直觉 / Core Intuition

训练目标看起来很简单，但背后隐藏任务很丰富。为了预测下一个 token，模型常常必须判断主题、语法、实体、长程依赖和用户意图。decoder-only Transformer 的训练效率高，是因为一个 sequence 里的所有 next-token losses 可以在一次并行 forward pass 里算完。

Base model 本质是 document continuer；instruction-tuned model 才更像 assistant。这就是 Lecture 19 要区分 pre-training 和 post-training 的原因。

Training pipeline. Pre-training 在 massive unlabeled text 上做 self-supervised NLL；SFT 用人工 instruction-response pairs 做 imitation；RLHF 用 human preferences / rankings 把输出推向 helpful、honest、harmless。

RL view. LLM reinforcement learning 里，state 是 prompt 加已经生成的 tokens，action 是 next token，policy 是模型的 next-token distribution。GRPO-style methods 会比较同一个 prompt 的多个 completions，用组内相对分数估计 advantage，不单独训练 value model。

  • Encoder-only model，比如 BERT：用 bidirectional attention 和 masked language modeling，适合 classification / NLU。
  • Decoder-only model，比如 GPT：用 causal attention 和 next-token prediction，适合开放式 generation。
  • Vision Transformer / ViT：把 image 切成 patches，当成 tokens 交给 Transformer encoder；因为少了 CNN 那种 locality inductive bias，通常更吃数据。

4. 核心公式 / Key Equations

Autoregressive factorization

$$ P_\theta(x_1,\ldots,x_T)=\prod_{t=1}^{T}P_\theta(x_t\mid x_{\lt t}) $$

符号. $x_t$ 是第 $t$ 个 token；$x_{\lt t}$ 表示它前面的所有 tokens；$T$ 是 sequence length；$\theta$ 是模型参数。

怎么理解. 语言模型给整句话打概率，是一个 token 一个 token 预测出来的。整段序列的概率，就是每一步 next-token probability 的乘积。

怎么用. 推 loss 时先对乘积取 log，把 product 变成 sum，再加负号得到 NLL。

Next-token probability

$$ P_\theta(x_t=i\mid x_{\lt t})=\frac{\exp(z_{t,i})}{\sum_{j\in V}\exp(z_{t,j})} $$

符号. $z_{t,i}$ 是位置 $t$ 上 token $i$ 的 logit；$V$ 是 vocabulary set；$j\in V$ 表示分母要对所有候选 token 求和。

怎么理解. LM head 会对 vocabulary 里的每个 token 给一个 logit，softmax 把这些 logits 转成概率分布。

怎么用. 比较两个候选 token 时看 logits 大小；要算真实概率时，对每个 logit 取 exp，再除以整个 vocabulary 的 exp 总和。

Token embedding plus position

$$ h_t^{(0)}=E[x_t]+p_t,\qquad E\in\mathbb{R}^{|V|\times D} $$

符号. $E$ 是 learnable token embedding table；$|V|$ 是 vocabulary size；$D$ 是 hidden size；$E[x_t]$ 是 token $x_t$ 对应的 row vector；$p_t$ 是第 $t$ 个位置的 positional encoding / position embedding。

怎么理解. Token ID 本身只是一个 index。模型先把它查表变成 $D$ 维向量，再加上位置信息，因为没有 position 的 self-attention 对 token order 是 permutation equivariant。

Position detail. 原始 Transformer 用 fixed sinusoidal signals；很多 LLM 使用 learned 或 rotary variants。考试层面的核心相同：给模型注入顺序信息。

怎么用. 算参数量时，input embedding table 大约贡献 $VD$ 个参数。如果 output embeddings / LM head 不共享，还要再算一个 $VD$。

NLL / cross-entropy loss

$$ \mathcal{L}(X;\theta)=-\frac{1}{T}\sum_{t=1}^{T}\log P_\theta(x_t\mid x_{\lt t}) $$

符号. $X=(x_1,\ldots,x_T)$ 是 token sequence；$T$ 是 sequence length；$\theta$ 是 model parameters；$P_\theta(x_t\mid x_{\lt t})$ 是模型给第 $t$ 个正确 next token 的 probability。

怎么理解. 如果模型给真实 next token 的概率低，$-\log p$ 就大，loss 就高。除以 $T$ 是为了让不同长度样本可比较。

怎么用. 如果正确 tokens 的概率是 $p_1,\ldots,p_T$，直接代入 $-\frac1T\sum_t \log p_t$。

Perplexity

$$ PP(X)=\exp(\mathcal{L}(X;\theta))=\left(\prod_{t=1}^T P_\theta(x_t\mid x_{\lt t})\right)^{-1/T} $$

符号. $PP(X)$ 是 perplexity；$\mathcal{L}(X;\theta)$ 是 average NLL；product 把每个位置的 correct-token probability 相乘；指数 $-1/T$ 把它变成 inverse geometric mean。

怎么理解. Perplexity 是 average NLL 的指数。$PP=4$ 可以理解成：平均每一步像是在 4 个同样可能的 token 里猜。

怎么用. 先算 average NLL，再取 exp。如果每个正确 token 概率都等于 $p$，perplexity 就是 $1/p$。

Temperature decoding

$$ P_T(i)=\mathrm{softmax}\!\left(\frac{z_i}{T}\right) $$

符号. $z_i$ 是 candidate token $i$ 的 logit；这里 $T>0$ 是 decoding temperature，不是 sequence length；$P_T(i)$ 是 logits 除以 temperature 再 softmax 后的 sampling probability。

怎么理解. Temperature 是在 softmax 前缩放 logits。小 $T$ 让分布更尖锐，大 $T$ 让分布更平。

怎么用. 任何有限 $T>0$ 都不会改变 greedy top-1，因为除以正数不改变 logits 排序。但 sampling 会变：小 $T$ 更保守，大 $T$ 更随机。

LoRA update

$$ W = W_0+\Delta W,\qquad \Delta W=BA,\qquad r\ll \min(d,k) $$

符号. 如果 $W_0\in\mathbb{R}^{d\times k}$，则 $B\in\mathbb{R}^{d\times r}$，$A\in\mathbb{R}^{r\times k}$。$r$ 远小于 $d,k$，所以更新很便宜。

怎么理解. LoRA 冻结原始权重 $W_0$，只学习一个低秩更新 $\Delta W$，而不是重新训练整个大矩阵。

怎么用. 参数量从完整矩阵的 $dk$ 变成 $dr+rk$。如果是 square $D\times D$ matrix，有些笔记会等价写成 $\Delta W=AB$，其中 $A\in\mathbb{R}^{D\times R}$、$B\in\mathbb{R}^{R\times D}$，trainable parameters 是 $2DR$ 而不是 $D^2$。

Decoder-only parameter count

$$ N_{\mathrm{params}}\approx L(4D^2+2DF)+2VD $$

符号. $L$ 是 decoder layers 数量；$D$ 是 hidden size；$F$ 是 MLP hidden width；$V$ 是 vocabulary size。

怎么理解. 每层 attention 大约有 $4D^2$ 参数，对应 $Q,K,V,O$ 四个 projection；MLP 有 $2DF$ 参数，对应两层 linear maps；$2VD$ 是 input/output embedding matrices。

怎么用. 这是 HW4 风格的 quick parameter count。通常忽略 bias、LayerNorm 等小项；如果 input/output embeddings tied，embedding 那项会改变。

5. 例题讲解 / Worked Examples

Lecture 19：三个 token 概率算 perplexity

出处：Lecture 19，题意转述。

如果模型对三个真实 next tokens 都给了 $0.25$ 的概率：

$$ PP=(0.25\cdot 0.25\cdot 0.25)^{-1/3}=4 $$

解释：平均来说，模型像是在 4 个同样可能的 token 中猜。

Lecture 18：temperature 会不会改变 top-1?

Temperature 只是把所有 logits 除以同一个正数 $T$。最大 logit 仍然最大，所以 greedy top-1 不变。但 sampling 会变：小 $T$ 更尖锐，大 $T$ 更平。

Lecture 18：decoding menu

Greedy decoding 每一步选最可能的 next token，容易陷入 repetition。Beam search 每一步保留 top $B$ 条 partial sequences。Top-k 和 top-p sampling 先限制候选集合再采样，用 coherence 和 diversity 做 tradeoff。

HW4 §2.4：decoder-only 参数量估算

HW4 的 OLMo-style 配置代入 $L(4D^2+2DF)+2VD$，约为 5.45B parameters。这说明 FFN width 和 vocabulary matrices 都是参数大头。

Lecture 19：prompting 和 in-context learning

Zero-shot prompt 只给任务要求；few-shot prompt 在 prompt 里给几个 input-output examples，让模型不用 gradient update 也能推断模式；chain-of-thought prompt 要求模型写出 intermediate reasoning，常能提升 multi-step reasoning tasks。

6. 解题技巧 / Problem-Solving Tips

  1. 训练目标题：先写 autoregressive factorization，再取 negative log。
  2. Perplexity 记住一句：average NLL 的指数。
  3. Tokenization 题：比较 word-level、character-level、subword BPE 的 tradeoff。
  4. Post-training 题：SFT 是模仿 demonstrations；RLHF 是优化 human preferences，常把 generation 看成 token-level MDP。
  5. Decoding 题：区分“怎么选 token”和“概率分布如何改变”。
  6. Greedy 每步选最高概率 token；beam search 保留 top $B$ 条 partial sequences；top-k 在概率最高的 $k$ 个 tokens 里采样；top-p 在 cumulative probability 达到 $p$ 的最小候选集合里采样。
  7. 参数量题记住 attention $4D^2$、MLP $2DF$、input/output embeddings $2VD$ 这个 HW4 简化口径。
  8. Prompting 题：zero-shot 没有 examples，few-shot 有 prompt examples，in-context learning 不做 gradient update。

7. 常见错误 / Common Mistakes

  • 把 base model 当成 instruction follower。base model 主要是 document continuer。
  • SFT 时忘记 mask system/user tokens，只应该让 assistant target 部分产生主要 loss。
  • 以为 perplexity 低就代表更安全、更真实。它只衡量 predictive likelihood，不衡量 truth。
  • 忘记 Transformer 需要 position information；只有 token embeddings 不能表达顺序。
  • 把 beam search 和 sampling 混为一谈。Beam search 是找 high-likelihood sequences；sampling 是主动加入 randomness。
  • 无过滤地从全部 tokens 采样，可能抽到极低概率的奇怪 token。
  • 以为 LoRA 更新整张矩阵。LoRA 是冻结 $W_0$，训练低秩矩阵 $A,B$。

  • Embeddings 用 $V\times D$ table；positional encoding 提供 token order。
  • BERT 是 encoder-only；GPT 是 decoder-only；ViT 把 image patches 当 tokens。
  • LM head 把 hidden state 映射到 vocabulary logits。
  • Perplexity = $\exp(\text{average NLL})$。
  • Greedy、beam search、top-k、top-p、temperature 都是 decoding choices。
  • SFT 教 instruction following；RLHF 对齐 HHH-style preferences。
  • LLM RL 把 next-token generation 当成 policy actions。
  • LoRA 训练 low-rank adapters，不训练整张矩阵。
  • Few-shot 和 chain-of-thought 是 prompting methods，不是 gradient updates。
